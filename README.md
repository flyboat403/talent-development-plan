# 职业教育人才培养方案编制技能

> **talent-development-plan** — 基于《专业教学标准》与《职业分析报告》双源融合，自动生成符合国家规范的职业院校人才培养方案（Markdown → DOCX）。
>
> **当前版本**：v0.5.0

---

## 一、它能做什么

| 能力 | 说明 |
|------|------|
| **自动检索教学标准** | 输入专业名称+层次，自动从内置库（1443条专业目录 / 579条PDF索引 / 274个专业简介）获取教学标准，无需手动上传 |
| **双源融合生成** | 教学标准（课程/学时/培养目标） × 职业分析报告（岗位/学习领域LD/职业能力） → 逐章生成完整方案 |
| **合规自动校验** | 学时、公共基础课比例、选修课比例、实践比例、周学时峰值全部按国标校验 |
| **交互确认** | 课程体系生成后暂停，呈现清单供用户审核调整（最多3轮） |
| **标准交付** | 输出 Markdown + DOCX（含课程体系架构图、11张规范表格、正式公文样式） |

## 二、使用方法（快速开始）

### 步骤 0：准备输入材料

| 材料 | 必需 | 说明 |
|------|:----:|:-----|
| **专业名称 + 教育层次** | ✅ | 如"机械加工技术（660102）中职"、"数字媒体技术（510204）中高职一体化" |
| **职业分析报告** | ✅ | 该专业的岗位调研/职业分析报告（PDF/DOCX/TXT） |
| **专业教学标准** | ⬜ | 可选。不提供则**自动检索**，也可手动上传（PDF/DOCX）覆盖 |

### 步骤 1：安装依赖

```bash
# Python 依赖
pip install pandas openpyxl markitdown==0.1.1 python-docx==1.1.2 pdfplumber==0.11.4 Pillow==11.1.0

# 系统依赖（Ubuntu/Debian）
apt-get install pandoc fonts-wqy-microhei

# macOS
brew install pandoc
```

### 步骤 2：运行生成流程

对 AI 助手说一句话即可触发完整流程，**推荐表述**：

```
使用"机械加工技术（660102）中职"和test目录下的职业分析报告，生成人才培养方案
```

系统将按 6 阶段自动执行：

```
Phase 0.5 自动检索教学标准（可选）→ 未提供则跳过
Phase 0   预处理输入文档（PDF/DOCX → Markdown，保留表格）
Phase 1   解析模板结构（自动选择中职/高职/一体化模板）
Phase 2   提取教学标准数据（培养目标/课程体系/学时/师资）
Phase 3   提取职业分析报告数据（岗位/学习领域/职业能力）
Phase 4   融合生成（课程体系双源合并 → 交互确认 → 学时合规）
Phase 5   输出交付（生成MD → 自检 → 转DOCX → 格式自检）
```

### 步骤 3：获取输出

```
output/<专业名称>专业/
├── <专业>人才培养方案.md          ← Markdown 源文件
├── <专业>人才培养方案.docx        ← 最终交付 Word 文件
└── images/
    └── 课程体系架构图.png         ← 已嵌入 DOCX 的架构图
```

> 💡 **交互确认**：生成课程体系后，系统会暂停呈现课程清单（含来源标签、LD编号、学时）。你可选择：直接生成 / 删除课程 / 添加课程 / 既删又加。确认后继续。

## 三、使用步骤详解（完整工作流）

### 方式一：自动检索（推荐，无需教学标准）

仅提供专业名称和教育层次，系统自动从内置数据源检索教学标准：

```
用户输入（专业名称 + 层次）
        ↓
Step 1: 从 XLSX 专业目录检索 → 专业代码 + 专业类代码
        ↓
Step 2: 用专业代码查 PDF 索引 → 教学标准 PDF URL
        ↓
Step 3: 无 PDF → 用类代码查专业简介目录 → 专业简介
        ↓
Step 4: 均未找到 → 提示用户上传教学标准
```

### 方式二：手动上传（特定版本教学标准）

若需特定版本教学标准，直接上传 PDF/DOCX 文件，系统跳过自动检索进入 Phase 0 预处理。

### 方式三：中高职一体化

输入层次标注"中高职一体化/五年制/3+2"，系统自动组合中职+高职模板，课程体系区分 ZZ（中职段）/GZ（高职段）标记，教学进程按 6 学期编排。

### Phase 5 交付细节（自检通过后才转 DOCX）

```
Step 5.1 生成完整 Markdown（含课程体系架构图）
   ↓
Step 5.2 自检 MD 内容（章节/学时/表3无代码/课程思政/1+X术语…）
   ↓    ← 全部通过才继续，否则回到 5.1 修复
Step 5.3 pandoc 转换 → postprocess_docx.py 后处理
   ↓
Step 5.4 自检 DOCX 格式（图片嵌入/表格边框/表头加粗/页边距）
```

## 五、关键规则与国标

### 核心规则 A/B/C/D

| 规则 | 内容 |
|------|------|
| **规则A** | 课程体系架构图必须嵌入 MD，PNG 保存到 `images/` 子目录 |
| **规则B** | 表4 公共基础课必须从模板提取国家标准内容，仅允许专业名称替换和学时调整 |
| **规则C** | 其余章节基于教学标准+职业分析报告融合生成 |
| **规则D** | 专业课程目标必须从双源材料提取整合，禁止 LLM 纯推理生成 |

### 学时底线

| 层次 | 总学时 | 公共基础课 | 选修课 | 实践 |
|------|--------|-----------|--------|------|
| 中职（三年制） | ≥3000 | ≥33% | ≥10% | ≥50% |
| 高职（三年制） | ≥2500 | ≥25% | ≥10% | ≥50% |
| 一体化（五年制） | ≥4500 | ≥25% | ≥10% | ≥50% |

### 学分换算规则（4.2.1）

专业课程学时换算学分，按优先级：**整除16 → 整除18 → 向下取整**（⌊学时÷16⌋）；纯实践课按 30学时/学分。公共基础课学分遵循模板表4。

### 周学时峰值容忍

每学期目标 28-32 学时；第 3-5 学期专业核心课密集期可放宽至 **30-36**，**上限 36**，超过必须调整。

## 六、自检验收

生成完成后自动执行**两阶段自检**（约40项），全部通过才交付：

### 阶段一：MD内容自检（转DOCX前）
- [x] 章节完整性、表格列数与样例一致
- [x] 无残留占位符或"XX"文本
- [x] 学时学分计算正确、表9/表10数据一致
- [x] 课程体系架构图已生成且相对路径引用正确
- [x] 表4公共基础课复用模板原文（规则B）
- [x] 能力条目采用"能力+行动"结构
- [x] 表3职业能力列无代码编号
- [x] 每门专业课程素质目标含课程思政元素
- [x] 全文无"1+X"字样，统一为"职业技能等级证书"

### 阶段二：DOCX格式自检（转换后）
- [x] DOCX 可正常打开、排版无错乱
- [x] 所有表格有边框（postprocess_docx.py 已执行）
- [x] 表头行加粗居中、正文字号统一
- [x] 架构图已嵌入（inline_shapes ≥ 1）
- [x] 无中间产物（方案_no_border.docx）残留

## 七、技术架构

### 生成流程（6 Phase）

| Phase | 内容 | 关键操作 |
|:-----:|:-----|:---------|
| **0.5** | 自动检索 | 专业目录 → PDF URL → 专业简介 |
| **0** | 预处理 | PDF/DOCX → Markdown（保留表格） |
| **1-3** | 数据提取 | 教学标准课程 + 职业报告学习领域 |
| **4** | 融合生成 | 双源映射、合并课程、学时分配、交互确认 |
| **5** | 输出交付 | 架构图 → 自检MD → pandoc → 后处理 → 自检DOCX |

### 关键技术

- **预处理降级链**：markitdown → python-docx/pdfplumber
- **文档转换**：pandoc（含 `--reference-doc` 正式公文样式）
- **架构图**：Pillow 绘制，中文字体自适应（wqy-microhei / msyh / PingFang）
- **DOCX后处理**：表格边框、表头加粗居中、页边距设置
